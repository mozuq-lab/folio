# Folio

好奇心を育てる日本語RSSリーダーです。RSSの閲覧・保存に、読書プラン、生成AIによる評価や出典付きの質問、ノート、端末間同期を組み合わせています。

ご自身のCloudflare Workers・D1へ配置する場合は、[Cloudflareへの移行手順](docs/self-host-cloudflare.md)を参照してください。FolioはCloudflare専用です。Cloudflare Accessの本人限定ログインと、JSONバックアップからの復元に対応しています。

## 画面と機能

- **For You**：関心度と重要度を別々に表示。トピック、リアクション、自然文の好みを反映します。一覧の上の絞り込みタブに出すトピックは、好みの設定で興味とは別に選べます（選ばなければテクノロジー・デザイン・ビジネス・サイエンス・暮らし）。「AIで選び直す」で未読の上位300記事を見出しだけでAIに評価させます（50記事ずつ送ります）。AIは記事のトピック（13個の候補から0〜3個）も付け、評価した記事はこのタグで興味との一致や絞り込みを判定します（AIがタグを付けなかった記事は言葉の規則のタグのまま。「興味あり／興味なし」の学習と保存には言葉の規則のタグを使います）。評価していない記事は、見出し・概要・RSSのカテゴリに含まれる言葉でタグを付けます（どれにも当てはまらない記事にはタグを付けません）。記事の見出しと画像は元記事へのリンクで、中クリックやコンテキストメニューから新しいタブで開けます。AI未評価の記事は字句・新しさ・掲載状況からの推定であることを表示します。
- **今日のダイジェスト**：5／10／15分の未読記事プラン。すぐ使える記事概要の抜粋と、AIによる要約を区別して表示します。
- **ナレッジノート**：保存記事、メモ、ハイライトを検索。保存した資料にAIで質問し、原文の引用と記事へのリンクを表示します。引用がない回答はアプリ側の根拠不足メッセージに置き換えます。
- **新しい発見**：いつもの関心の外にある記事を提案し、For Youへ混ぜる割合を設定できます。メディア・話題の反復を抑える多様性設定とは別の設定です。
- **フィード管理**：RSS／Atomの追加・更新・解除、OPMLのプレビュー付き取り込みと書き出し。重複を除き、入れ子の分類を保持します。購読中のフィードは名前かURLで検索できます。
- **サイトのURLから追加**：追加欄にはRSS／AtomのURLのほか、サイトやブログのURLも入力できます。ページの `<link rel="alternate">` でRSS／Atomが指定されていれば、そのフィードを購読します（購読するURLは見つけたフィードのURLです）。指定が2つ以上あれば候補（名前とURL）を表示し、選んだものを追加します。指定が無いときは、RSS／AtomのURLを直接入力してください。`/feed` などのURLの推測や、ほかのページの巡回はしません。
- **分類と並び順**：フィード管理で分類を作成・名前の変更・削除でき（「未分類」「すべて」は名前に使えません）、分類の順と、分類の中のフィードの順をドラッグか ↑↓ で並び替えられます。1つのフィードを複数の分類に入れられます。どの分類にも入っていないフィードは「未分類」に表示します。
- **フィードのアイコン**：各サイトのファビコンを表示します。Folioのサーバーが、サイトのトップページで指定されたアイコン、無ければ `/favicon.ico` を取得します。ブラウザーには1週間キャッシュします。独自ドメインで公開している場合はサーバーでもサイトごとに1週間キャッシュします（workers.devではサーバーのキャッシュは効きません）。外部のファビコン配信サービスは使いません。取得できないサイトは頭文字を表示します。
- **記事詳細**：RSS概要に加え、取得可能な公開HTTPS記事の本文を抽出。文章を選択してハイライトし、メモと一緒に保存できます。アクセス制限された本文を回避して取得しません。
- **定期取得**：Cloudflareの定期実行（5分ごと）が、購読中のフィードを順番に取得してD1にためます。1回に取得するのは優先フィード1件と通常フィード1件で、どちらも最後の取得が最も古いものから選びます。優先フィードが無いときは通常フィードを2件取得します。ためた記事は90日分保持します。
- **フィードを更新**：一覧の上のボタンです。フィードを表示しているときはそのフィードだけ、それ以外の画面では購読中のすべてのフィードを、サーバーで4件ずつ並行して取得します（1回のリクエストで取得するのは1フィード）。取得できなかったフィードがあれば、件数（1件だけ頼んだときは名前・理由・URL）を表示します。
- **優先して取得**：フィード管理で、フィードごとに「優先して取得」を選べます。選べるのは5件までです。フィード管理には、フィードごとの最後の取得日時と失敗の有無も表示します。
- **購読の見直し**：フィード管理には、フィードごとに「届いた記事」（取得してためている直近90日分の記事の数）と「うち保存」（そのうち一度でも「あとで読む」に入れた記事の数）も表示します。保存を解除した記事も数え、同じ記事を2回数えることはありません。解除した記事を数えられるのは、この機能を入れたあとに保存または解除した記事です。記録は同期データに記事のIDと日時だけを持ち、3,000件を超えた分は古いものから消します。
- **端末間同期**：ログイン中の利用者ごとに購読・既読・保存・メモ・好み・AI結果をD1へ保存。変更が競合した場合は自動上書きせず、残す内容を選べます。

検索、未読表示、「すべて既読にする」（表示中の一覧の未読をまとめて既読）、新着／おすすめ順、カード／リスト／コンパクト表示、スマートフォン表示、JSONバックアップも利用できます。既存のブラウザー保存データは移行します。

記事一覧では丸印／チェック印で既読・未読を切り替えられます。「元記事」は詳細画面を開かずに新しいタブへ移動し、その記事を既読にします。記事タイトルからはFolio内の詳細を開けます。コンパクト表示はPCで見出しを1行にし、スマートフォンでは見出しと操作を2段に配置します。

**ダークモード**：明るい配色と暗い配色に対応しています。サイドバーの下にある「配色」で、「自動」（端末の設定に合わせる。既定）・「ライト」・「ダーク」から選べます。スマートフォンでは左上のメニューを開くと表示されます。選んだ配色はその端末にだけ保存し、同期しません。

## 定期取得と記事のバックログ

- **取得のしくみ**：Cron Trigger（`*/5 * * * *`）が5分ごとに動きます。取得対象は、直近90日以内にFolioを開いた利用者で、`allowedEmails` に含まれる人の購読フィードです。優先フィード（最大5件）の目安は約25分ごと、通常フィードが25件の場合の目安は約2時間ごとです。1フィードの取り込みは200記事までです。
- **保存先**：定期取得した記事は、利用者ごとにD1の `folio_articles` へ90日間ためます（基準は取得日時）。90日を過ぎた記事は1日1回の定期実行で削除します。削除した記事は、フィードに載り続けていても取り込み直しません（未読に戻って一覧に再び出ることはありません）。そのために、削除した記事のIDとURLをD1の `folio_expired` に1年間残します。端末は差分だけを受け取り、ブラウザーのIndexedDBに保存します。同期データ（4MiB）には、保存・メモ・AI回答で参照している記事だけを持ちます。これらは90日を過ぎても消えません。
- **既読**：保持対象でない記事の既読はD1の記事に、保持対象の記事の既読は同期データに保存します。オフラインで既読にした操作は端末に残り、接続後に送ります。
- **For You**：端末にある未読記事すべてを候補に並べ替えます。既読にした記事はその場では消えず、「フィードを更新」するか画面を開き直したときに並び直します。差分で届いた新着は「新着{n}件」と表示し、並び直すまで混ぜません。
- **すべて既読にする**：一覧の上のボタンです。確認ダイアログに件数を表示し、記事IDを1,000件ずつ分けて送ります。途中で失敗しても、既読にできた分はそのままです。残りは再試行できます。無料プランでは、非常に多い件数を一度に既読にするとD1の1日の書き込み枠に達し、一部だけ既読になって再試行の表示が出ることがあります。その場合は翌日に続けてください。
- **バックアップの範囲**：JSONバックアップには同期データ（購読・好み・保存・メモ・AI回答で参照している記事とその既読）が入ります。90日分のバックログと、それ以外の記事の既読は含まれません。古い形式のバックアップを読み込むと、中の記事と既読をバックログに取り込みます。
- **ローカル開発**：`npm run dev` では定期取得は動きません。画面を最初に開いたとき（まだ一度も更新していないとき）は全フィードを1回取得します。「フィードを更新」ボタンとフィードの追加でも取得します。
- **制限**：バックログの同期は、1つの端末でFolioのタブを1つだけ開いて使ってください。2つ開くと、送信前の既読や取得位置を互いに上書きすることがあります。

## 起動と検証

Node.js 24以上が必要です（`.nvmrc` は `24`）。

```sh
npm ci
npm run dev
```

ターミナルのLocal URLを開きます。ローカルにはログイン画面がありません。開発サーバーで動かしている間、loopback（`127.0.0.1`）からのアクセスには固定の開発用利用者を割り当てます。この仕組みは本番のビルドに含まれません。含まれた場合はビルドを失敗させます。

```sh
npm test
npx tsc --noEmit
npm run lint
npm run build
```

`npm run dev`・`build`・`start` はすべてCloudflare版です。`build` は `.folio/deploy/wrangler.json` を生成します。`npm run start` は本番用のビルドをローカルで動かします。Cloudflare Accessで保護されるため、Accessの設定がないとリクエストは503または403になります。ビルドの確認用で、画面を操作するときは `npm run dev` を使ってください。ツールの作業用フォルダーは `.folio/tools` です。

## ローカルDB

ローカルのD1は `.folio/local-state` に保存します。初回と、`drizzle/` にmigrationが増えたとき（バックログ機能の `0002`・`0003`、削除した記事の印の `0004` を含む）は、ビルドしてから未適用のmigrationをすべて適用してください。適用済みのものは自動で飛ばされます。これを行わないと同期と記事の取得が失敗します。

```sh
npm run cloudflare:build
node --import ./scripts/tool-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 migrations apply DB --local --config .folio/deploy/wrangler.json --persist-to .folio/local-state
```

本番のDBへの適用は、[Cloudflareへの移行手順](docs/self-host-cloudflare.md)の `cloudflare:bootstrap`／`cloudflare:db:migrate` で行います。

## 生成AI

サーバーから次の4つの提供元を使えます。

| 提供元 | Secretまたはバインディング | 既定のモデル |
| --- | --- | --- |
| OpenAI | `OPENAI_API_KEY` | `gpt-6-luna` |
| Claude | `ANTHROPIC_API_KEY` | `claude-haiku-5-5` |
| OpenRouter | `OPENROUTER_API_KEY` | `openai/gpt-6-luna` |
| Workers AI | バインディング `AI` | `@cf/meta/llama-3.3-70b-instruct-fp8-fast` |

キーはCloudflare Secretにだけ保存します。ブラウザー、D1、Gitには渡しません。登録は `npm run cloudflare:secret -- <キー名>` または `npm run cloudflare:secret-from-env -- <環境ファイル> <キー名>` で行います。以前の `OPENAI_MODEL` は廃止しました。モデルは画面で選びます。

提供元・モデル・推論の深さは、画面の「あなたらしいおすすめに」（好みの設定）で選びます。

- 提供元：キーを設定していない提供元は「キー未設定」と表示します。Workers AIはローカル開発では「この環境では使えません」と表示します。
- モデル：候補から選ぶか、モデルIDを直接入力します。
- 推論の深さ：既定は `medium` です（Workers AIには推論の深さの設定がなく、常に「モデルに任せる」になります）。「モデルに任せる」を選ぶと推論の設定を送りません。深いほど時間と費用がかかります。
- 設定はD1に保存し、端末間で同期します。

選択がない場合は、キーのある提供元を `anthropic`、`openai`、`openrouter` の順に自動で選びます。Workers AIは自動では選びません。保存済みの提供元のキーを後から削除した場合も、別の提供元へは切り替えず、設定を求める表示になります。

Workers AIのバインディング `AI` は、本番の設定に常に含まれます。利用料はCloudflare側で請求されます。

AIは対象のボタンを押したときだけ実行します。その操作に必要な記事、好み、質問、関連ノートを送信し、OpenAIには `store:false`（応答を保存しない設定）を付けて依頼します。Claude、OpenRouter、Workers AIでは同様の設定を送らないため、データの保持は各提供元の規約に従います。取得済み本文がない記事はRSS概要だけを対象とします。本文全体を読んだかのように扱いません。

出力は構造化されたJSONを要求し、記事ID、引用文の実在、読書時間の予算などをアプリ側で検証します。利用者ごとに1分6回の制限があります（Workerのメモリー内の補助的制限）。この制限は提供元に関係なく数えます。各提供元の管理画面で、利用額の上限を設定してください。

OpenAIとOpenRouterへの通信は `redirect: manual` を指定し、別URLへ認証情報を転送しません。キーを設定した提供元がない場合はAI未接続と表示します。RSS閲覧・ローカル推薦・読書プラン・ノート・同期はそのまま利用できます。

更新時、旧版の画面を開いたままの端末やタブは、新しい形式を扱えないため再読み込みが必要です。

## 保存と同期

ブラウザーにはoffline用cacheを保持します。D1には同じ利用者のライブラリを保存し、別端末でも読み込めます。サーバーのrevisionによる楽観的排他で競合を検知します。アカウントが変わった場合、以前の利用者のcacheを新しい利用者へ送信・表示しません。

クラウド同期は1ライブラリ4MiBまでです。D1の行サイズ制限に合わせて512KiB以下のUTF-8断片へ分け、metadataの更新・断片保存・旧断片の削除をtransactional batchで処理します。上限を超えた場合は端末の内容を保持し、同期エラーとバックアップ操作を表示します。端末の保存容量にも制限があります。

記事の更新や購読解除後も、保存・既読・ノート・AI回答などで参照されている元記事を保持します。プロフィール横のダウンロードボタンはメモ・好みを含むJSONバックアップを作ります。記事のバックログ（90日分）は含みません（詳しくは「定期取得と記事のバックログ」）。

## 取得とセキュリティ

- RSS／Atom：公開HTTPS、redirect再検査、10秒timeout、2MiB／1フィード200記事、XML検証、DOCTYPE拒否、5分cache。
- フィードの発見（追加のときだけ）：入力したURLがHTMLを返した場合に、先頭256KiBの `<head>` から `<link>` を読みます。取得の条件はRSSと同じです（公開HTTPS、redirect再検査、10秒timeout）。候補のURLは転送後の最終URLを基準に解決し、1件ずつ公開HTTPSか確かめ、通らないものは捨てます。候補は10件、名前は120文字までです。取得したHTMLは描画せず、名前は文字として表示するだけです。定期取得と「フィードを更新」では、フィードのURLがHTMLを返したら失敗として扱います。
- 公開記事本文：HTTPSとredirect再検査、10秒／2MiB、Readabilityによるテキスト抽出。任意のHTMLを画面に描画しません。
- OPML：1MiB／500フィード、DOCTYPE／entityと危険URLを拒否。
- 同期・AI・本文API：Cloudflare Accessの認証を検証し、書き込みはsame-originを確認します。

Cloudflare Accessで本人限定にして公開します。初期表示のサンプルは明示し、実フィードの取得後に差し替えます。
